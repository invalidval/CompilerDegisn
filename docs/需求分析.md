**版本**: 1.0  
**依据**: 《编译原理与技术课程设计》-202601(2).pdf  
**适用范围**: 课程设计与实现全过程

## 1. 项目概述

### 1.1 任务目标
按照所给 **Pascal-S 语言** 的语法和语义，设计并实现一个完整的编译程序，将 Pascal-S 源代码翻译为 **C 语言** 目标代码。

### 1.2 核心要求
- **源语言**: Pascal-S (子集)
- **目标语言**: C 语言
- **分析方法**: LALR(1) (推荐 YACC/Bison) 
- **翻译技术**: 语法制导翻译 (SDT)
- **团队规模**: 5±1 人/组
- **交付物**: 可执行程序、完整源码、设计报告、测试报告

## 2. 源语言规范 (Pascal-S)

### 2.1 词法规范 (Lexical Specification)

#### 2.1.1 标识符 (Identifiers)
- **定义**: `id → letter (letter | digit)*`
- **规则**: 
  - 以字母开头，后跟字母或数字
  - **不区分大小写** (实现时必须统一转为小写或大写)
  - 建议最大长度限制: 8 字符
  - 示例: `program`, `Sort`, `MAX_VAL`

#### 2.1.2 关键字 (Keywords - 保留字)
| 类别 | 关键字列表 |
|------|----------|
| 程序结构 | `program`, `begin`, `end`, `const`, `var`, `procedure`, `function` |
| 类型 | `integer`, `real`, `boolean`, `char`, `array`, `of` |
| 语句 | `if`, `then`, `else`, `for`, `to`, `do`, `while` (可选扩充) |
| 输入输出 | `read`, `write` |
| 逻辑运算 | `and`, `or`, `not` |
| 其他 | `div`, `mod` |

#### 2.1.3 常数 (Constants)
- **整数**: `digits` (如 `123`, `-5`)
- **实数**: `digits.optional_fraction` (如 `3.14`, `-0.5`)
- **字符**: `'letter'` (单引号包裹的单字符，如 `'a'`, `'Z'`)
- **定义**: 
  ```
  digits → digits digit | digit
  optional_fraction → . digits | ε
  num → digits optional_fraction
  const_value → + num | - num | num | 'letter'
  ```

#### 2.1.4 运算符 (Operators)
| 类别 | 符号 | 说明 |
|------|------|------|
| 赋值 | `:=` | 赋值运算符 |
| 关系 | `=`, `<>`, `<`, `<=`, `>`, `>=` | 比较运算 |
| 加减 | `+`, `-`, `or` | 加法、减法、逻辑或 |
| 乘除 | `*`, `/`, `div`, `mod`, `and` | 乘法、除法、整除、取模、逻辑与 |
| 一元 | `not`, `-` (负号) | 逻辑非、取负 |

#### 2.1.5 分隔符与注释
- **空格**: 关键字前后必须有空格或换行；其他位置可选
- **注释**: `{ ... }` 
  - 可出现在任何单词之后
  - 支持嵌套？(文档未明确，认为不必须支持)
  - 编译器必须跳过注释，但需统计换行符以保持行号准确

#### 2.1.6 词法错误处理
- 非法字符
- 未闭合的注释
- 非法数字格式
- 标识符超长

### 2.2 语法规范 (Grammar Specification)

#### 2.2.1 完整文法产生式 (BNF)

```bnf
// 1. 程序结构
programstruct → program_head ; program_body .
program_head → program id ( idlist ) | program id
program_body → const_declarations var_declarations subprogram_declarations compound_statement

// 2. 列表定义
idlist → id | idlist , id

// 3. 常量声明
const_declarations → ε | const const_declaration ;
const_declaration → id = const_value | const_declaration ; id = const_value

// 4. 变量声明
var_declarations → ε | var var_declaration ;
var_declaration → idlist : type | var_declaration ; idlist : type
type → basic_type | array [ period ] of basic_type
basic_type → integer | real | boolean | char
period → digits .. digits | period , digits .. digits

// 5. 子程序声明
subprogram_declarations → ε | subprogram_declarations subprogram ;
subprogram → subprogram_head ; subprogram_body
subprogram_head → procedure id formal_parameter | function id formal_parameter : basic_type
formal_parameter → ε | ( parameter_list )
parameter_list → parameter | parameter_list ; parameter
parameter → var_parameter | value_parameter
var_parameter → var value_parameter
value_parameter → idlist : basic_type
subprogram_body → const_declarations var_declarations compound_statement

// 6. 语句
compound_statement → begin statement_list end
statement_list → statement | statement_list ; statement
statement → ε
           | variable assignop expression
           | func_id assignop expression      // 函数返回值赋值
           | procedure_call
           | compound_statement
           | if expression then statement else_part
           | for id assignop expression to expression do statement
           | read ( variable_list )
           | write ( expression_list )

else_part → ε | else statement

// 7. 表达式
expression → simple_expression | simple_expression relop simple_expression
simple_expression → term | simple_expression addop term
term → factor | term mulop factor
factor → num
       | variable
       | ( expression )
       | id ( expression_list )    // 函数调用
       | not factor
       | uminus factor             // 负号

// 8. 辅助定义
variable_list → variable | variable_list , variable
variable → id id_varpart
id_varpart → ε | [ expression_list ]
procedure_call → id | id ( expression_list )
expression_list → expression | expression_list , expression
func_id → id   // 用于赋值的函数名
```

#### 2.2.2 关键语法说明
1. **LALR(1) 文法**: 该文法天然适合 LR 分析，若采用递归下降需消除左递归
2. **程序结构**: 
   - 必须包含 `program` 头
   - 可选 `const`, `var`, `subprogram` 声明
   - 必须有 `begin...end` 主程序体
3. **嵌套规则**:
   - **过程和函数定义不允许嵌套** (平级声明)
   - **复合语句 (`begin...end`) 允许任意嵌套**
4. **递归调用**: 过程和函数可以递归调用自身
5. **歧义处理**: 
   - `factor → id` 既可是变量、常量，也可是无参函数调用
   - **必须在语义分析阶段通过符号表区分**

### 2.3 语义规范 (Semantic Specification)

#### 2.3.1 类型系统
| Pascal-S 类型 | C 语言映射 | 说明 |
|--------------|-----------|------|
| `integer` | `int` | 整型 |
| `real` | `float` 或 `double` | 浮点型 (建议 double) |
| `boolean` | `int` | 0=false, 非 0=true |
| `char` | `char` | 字符型 |

#### 2.3.2 作用域规则
- **全局作用域**: 程序头部声明的常量和变量
- **局部作用域**: 每个过程/函数内部声明的常量和变量
- **可见性**: 
  - 内层可访问外层变量 (静态作用域)
  - 同名局部变量屏蔽外层变量
- **生命周期**: 过程/函数退出时，局部符号从符号表移除

#### 2.3.3 参数传递机制
| 传递方式 | Pascal-S 语法 | C 语言实现 | 说明 |
|---------|--------------|-----------|------|
| 传值 (Value) | `x: integer` | `int x` | 复制实参值 |
| 引用 (Var) | `var x: integer` | `int *x` | 传递地址，调用时加 `&`，使用时解引用 `*` |

#### 2.3.4 数组处理
- **定义**: `array [lower..upper] of type`
- **维度**: 文档中 `period` 支持逗号分隔，说明有多维数组
- **下标偏移**: 
  - Pascal-S: `A[i]` (i 从 `lower` 开始)
  - C 语言: `A[i - lower]` (必须做偏移转换)
- **边界检查**: 访问越界

#### 2.3.5 必须实现的类型检查
1. **变量/函数声明检查**: 使用前必须声明
2. **重复定义检查**: 同一作用域内名字唯一
3. **类型兼容性**:
   - 赋值语句左右类型一致 (允许 integer→real 隐式转换)
   - 运算符操作数类型匹配
4. **数组访问**:
   - 下标表达式类型必须为 integer
   - 下标值在 `[lower, upper]` 范围内 (运行时或编译时检查)
5. **过程/函数调用**:
   - 参数个数匹配
   - 参数类型匹配 (考虑 var 参数的特殊要求)
   - 函数返回值类型与使用上下文匹配
6. **函数赋值**: `func_name := expression` 只能出现在函数体内

## 3. 功能模块需求

### 3.1 词法分析器 (Lexer)
**输入**: Pascal-S 源文件 (.pas)  
**输出**: Token 流 (供语法分析器消费)

**必须实现的功能**:
- [ ] 识别所有 Token 类型 (关键字、标识符、常数、运算符、分隔符)
- [ ] 标识符统一转为小写
- [ ] 过滤注释 `{...}`，但维护行号计数
- [ ] 记录每个 Token 的位置信息 (行号、列号)
- [ ] 词法错误检测与报告 (非法字符、未闭合注释等)
- [ ] 提供 `yylex()` 接口供 Bison 调用

**接口定义**:
```c
typedef enum {
    TOKEN_PROGRAM, TOKEN_BEGIN, TOKEN_END, /* ... 所有关键字 */
    TOKEN_ID, TOKEN_NUM, TOKEN_REAL, TOKEN_CHAR,
    TOKEN_ASSIGN, TOKEN_RELOP, TOKEN_ADDOP, TOKEN_MULOP,
    TOKEN_LPAREN, TOKEN_RPAREN, /* ... 所有符号 */
    TOKEN_EOF, TOKEN_ERROR
} TokenType;

typedef struct {
    TokenType type;
    char* value;      // 标识符/常数具体值
    int line;         // 行号
    int col;          // 列号
} Token;

Token yylex();  // 返回下一个 Token
```

---

### 3.2 语法分析器 (Parser)
**输入**: Token 流  
**输出**: AST (抽象语法树) 或 直接生成中间代码

**必须实现的功能**:
- [ ] 实现 LALR(1) 分析 (推荐 Bison/Yacc) 或 递归下降分析
- [ ] 构建 AST (推荐) 或在归约时直接执行语义动作
- [ ] 检测语法错误 (缺少分号、括号不匹配等)
- [ ] 错误恢复策略 (恐慌模式/短语级恢复)，继续分析后续代码
- [ ] 输出详细错误位置和信息
- [ ] 对文法冲突进行治理与验证：若出现 Bison 冲突告警（尤其 RR），需定位可空规则重叠并在不改变语义动作前提下完成消解

**分析方法选择**:
- **方案 A (推荐)**: Bison + Yacc
  - 优点: 自动处理冲突，稳定性高
  - 要求: 编写 `.y` 文件，定义产生式和语义动作
- **方案 B**: 手工递归下降
  - 要求: 消除文法左递归，手动编写预测分析表

---

### 3.3 语义分析器 (Semantic Analyzer)
**输入**: AST 节点 (在语法分析过程中构建)  
**输出**: 带注解的 AST (填充类型、符号表条目等信息)

**必须实现的功能**:
- [ ] **符号表管理**:
  - 数据结构: 支持多层作用域 (Hash 表 + 栈)
  - 操作: `insert()`, `lookup()`, `enterScope()`, `exitScope()`
  - 存储内容: 名字、类型、种类 (VAR/PROC/CONST)、数组界、参数列表
- [ ] **类型检查**:
  - 赋值兼容性
  - 运算符类型匹配
  - 函数调用参数验证
  - 数组下标类型验证
- [ ] **语义错误报告**: 未声明变量、类型不匹配、重复定义等

**符号表条目结构**:
```c
typedef enum { KIND_VAR, KIND_CONST, KIND_PROC, KIND_FUNC } SymbolKind;

typedef struct {
    char* name;
    SymbolKind kind;
    DataType type;           // integer, real, etc.
    
    // 常量专用
    double constValue;
    
    // 数组专用
    int arrayDims;
    int lowerBound[MAX_DIM];
    int upperBound[MAX_DIM];
    
    // 过程/函数专用
    int paramCount;
    struct ParamInfo {
        char* paramName;
        DataType paramType;
        bool isVarParam;     // true=引用传递，false=值传递
    } params[MAX_PARAMS];
    
    // 作用域信息
    int scopeLevel;
} SymbolEntry;
```

### 3.4 代码生成器 (Code Generator)
**输入**: 带注解的 AST  
**输出**: C 语言源代码 (.c 文件)

**必须实现的功能**:
- [ ] **类型映射**: Pascal-S 类型 → C 类型
- [ ] **声明生成**:
  - 常量: `#define` 或 `const`
  - 变量: 直接翻译
  - 数组: 计算实际大小，调整下标访问
  - 过程/函数: 处理参数 (var → 指针)
- [ ] **语句翻译**:
  - 赋值: `:=` → `=`
  - 条件: `if-then-else` → C 的 `if-else`
  - 循环: `for-to-do` → C 的 `for`
  - 复合语句: `begin-end` → `{}`
- [ ] **表达式翻译**:
  - 算术/逻辑运算符直接映射
  - 数组访问: `A[i]` → `A[i - lower_bound]`
  - 函数调用: 处理 var 参数的 `&` 和 `*`
- [ ] **输入输出**:
  - `read(x)` → `scanf("%d", &x)`
  - `write(x)` → `printf("%d", x)` (根据类型选择格式符)

**特殊处理要求**:
1. **数组下标偏移**: 必须根据声明的 `lower..upper` 生成 `index - lower`
2. **Var 参数**: 
   - 函数声明: `procedure p(var x: integer)` → `void p(int *x)`
   - 函数调用: `p(a)` → `p(&a)`
   - 函数体内: 使用 `x` → 使用 `*x`
3. **函数返回值**: 
   - Pascal: `func_name := value`
   - C: 需要引入局部变量 `_retval`，最后 `return _retval`

### 3.5 错误处理模块 (Error Handler)
**贯穿所有阶段**

**必须实现的功能**:
- [ ] 统一错误报告接口: `reportError(line, col, message)`
- [ ] 错误分类: 词法错误、语法错误、语义错误、代码生成错误
- [ ] 错误恢复:
  - 词法: 跳过非法字符
  - 语法: 恐慌模式 (同步到分号/END 等同步记号)
  - 语义: 记录错误，继续分析
- [ ] 错误计数: 超过阈值 (如 10 个) 停止编译

## 8. 开发约束与注意事项

### 8.1 严格约束
1. **不区分大小写**: 标识符必须统一处理
2. **注释处理**: 必须支持 `{}` 注释
3. **数组下标**: 必须处理偏移转换
4. **Var 参数**: 必须正确实现引用传递
5. **禁止嵌套定义**: 过程/函数不能嵌套声明

### 8.2 推荐实践
1. **使用 Bison/Flex**: 提高开发效率
2. **构建 AST**: 优于直接翻译，便于调试和优化
3. **分阶段开发**: 词法→语法→语义→代码生成，每阶段测试
4. **版本控制**: 使用 Git 管理代码
5. **持续集成**: 每日构建，及时发现问题

### 8.3 常见陷阱
- ⚠️ 忘记标识符转小写导致符号表查找失败
- ⚠️ 数组下标未做偏移转换导致运行时错误
- ⚠️ Var 参数忘记加 `&` 或 `*`
- ⚠️ 作用域退出时未清理符号表
- ⚠️ 错误恢复不当导致雪崩式报错
