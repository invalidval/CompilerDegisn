# 代码生成模块问题修复汇报

日期：2026-04-10  
模块：代码生成（Code Generation）  
范围：close_set 测试集相关失败用例与生成代码逻辑缺陷修复

## 一、工作背景

根据前期问题记录，项目在代码生成阶段存在多类错误，主要表现为：

1. 浮点计算结果严重偏差，部分样例输出趋近于全 0。
2. `read` 读入函数返回值场景生成非法 C 代码（如 `&getint()`、`&getfloat()`）。
3. 多字符字面量（如 `'--'`、`'Not exist'`）被生成为 `char`，触发编译器溢出告警与行为错误。
4. `break` 被错误地按过程调用生成（`break()`），导致语法报错。

本轮工作以 close_set 相关问题为主线，逐项定位根因并完成针对性修复。

## 二、问题定位与根因分析

### 1. 浮点结果偏差问题

现象：多个浮点测试用例计算结果与预期差异明显，出现大量 `0.000000` 或明显缩放失真。

根因：函数与过程参数类型在代码生成时错误读取 `typeNode->dataType`，在若干场景下该值为 `Unknown`，经默认映射后退化为 `int`，导致本应为 `real` 的参数被生成为 `int`，引发隐式截断与精度丢失。

### 2. `read` 场景的取地址错误

现象：生成代码出现 `scanf("%d", &getint())`、`scanf("%f", &getfloat())`，编译报错 `lvalue required as unary '&' operand`。

根因：Pascal 函数体内 `read(functionName)` 实际语义是“给函数返回值赋值”，但生成阶段将其当作普通函数调用表达式 `name()`，随后再统一加 `&`，形成非法右值取地址。

### 3. 多字符常量处理错误

现象：例如 `split = '--'`、`ne = 'Not exist'` 被生成为 `const char ...`，触发 `multi-character character constant` 与溢出告警。

根因：多字符字面量缺乏专门分支处理，按单字符常量路径映射为 `char`。

### 4. `break` 语句生成错误

现象：循环内 `Break` 被生成为 `break()`，编译报 `expected ';' before '(' token`。

根因：语法树中将其统一表示为过程调用节点，生成阶段未做关键字级别特判。

## 三、修复措施

本轮修复主要集中在以下文件：

- `src/codegen_utils.cpp`
- `src/code_generator.cpp`

### 1. 参数类型映射修复（浮点精度问题核心修复）

在函数/过程原型与定义生成逻辑中，参数类型统一改为从参数标识符读取（`id->dataType`），避免 `Unknown -> int` 的退化路径。

涉及函数：

- `emitProcPrototype`
- `emitFuncPrototype`
- `emitProcDecl`
- `emitFuncDecl`

### 2. `read` 函数返回值场景修复

在 `emitReadStmt` 中新增函数返回值读入分支：当表达式被生成为 `name()` 形式时，不再拼接 `&name()`，改为写入函数返回槽 `_retval`，生成 `&_retval`。

修复后：

- `scanf("%d", &_retval)`
- `scanf("%f", &_retval)`

### 3. 多字符字面量修复

新增多字符字面量识别与转换逻辑：

- 对 `'--'`、`'Not exist'` 等多字符字面量，不再按 `char` 生成；
- 常量声明改为字符串常量路径（`const char*`）；
- 写出语句同步使用 `%s` 格式化输出。

### 4. `break` 关键字特判修复

在 `visit(ProcCallNode*)` 中新增 `break` 分支，直接生成 `break` 语句体，不再走普通过程调用生成路径。

## 四、验证情况

本轮修复后已对关键问题样例进行生成与编译验证：

1. `84_union_find.pas`：`getint` 内部读入已生成为 `scanf("%d", &_retval)`，`&getint()` 报错消除。
2. `92_math.pas`：
   - `split` 生成为 `const char* split = "--"`；
   - `getfloat` 内部读入生成为 `scanf("%f", &_retval)`；
   - `write(split)` 对应输出路径为 `%s`。
3. `79_graph_coloring.pas`：循环中 `Break` 已生成为 `break;`，`break()` 语法错误消除。

说明：当前仍可能出现“比较表达式外层冗余括号”类编译告警，此类告警不影响本轮问题修复结论，且与本次四项缺陷无直接因果关系。
