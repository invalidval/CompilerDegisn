## 1. 模块目标与职责边界

### 1.1 模块目标
将词法分析输出的 Token 流解析为 AST，并输出 `ProgramNode*` 根节点，为语义分析与代码生成提供稳定输入。

### 1.2 职责边界
语法分析模块负责：
1. 文法规则定义与 Bison 归约。
2. 归约动作中的 AST 建树。
3. 语法错误检测与有限恢复。
4. 对外导出解析结果与解析入口桥接接口。

## 2. 代码与接口清单

### 2.1 核心文件
1. `src/parser.y`：Bison 文法与 AST 建树动作。
2. `include/parser_bridge.h`：解析桥接接口（供 main/语义/代码生成使用）。
3. `include/ast.h`：AST 契约（节点类型、字段、ListKind、SourcePos）。

### 2.2 对外接口
1. `ProgramNode* getParseResultRoot()`：获取当前解析得到的 AST 根。
2. `void resetParseResult()`：重置解析结果与 ASTBuilder 状态。
3. `ASTBuilder& getAstBuilder()`：获取建树器实例。
4. `int getParseErrorCount()`：获取本次解析累计语法错误数。
5. `int yyparse(void)`：执行语法解析。
6. `extern FILE* yyin`：输入流句柄。

## 3. 文法覆盖与 AST 映射概览

### 3.1 程序与声明结构
1. `program -> PROGRAM IDENTIFIER ... program_body '.'` 生成 `ProgramNode`。
2. `program_body` 生成 `BlockNode`，子槽位固定为 const/var/subprogram/compound。
3. `const_declarations`、`var_declarations`、`subprogram_declarations` 统一映射为 `ListNode(Declarations)`。

### 3.2 类型系统结构
1. `basic_type` 映射为 `IdentifierNode`（integer/real/boolean/char）。
2. `array [period] of basic_type` 通过 `buildArrayTypeFromRanges` 折叠为嵌套 `ArrayTypeNode`。
3. `period` 映射为 `ListNode(ArrayRanges)`，`range` 暂用 `ArrayTypeNode(lower, upper, nullptr)` 作为区间片段承载。

### 3.3 语句与表达式
1. 赋值：`variable ASSIGN expression` -> `AssignStmtNode`。
2. 条件：if-then-else -> `IfStmtNode`；通过优先级规则解决 dangling else。
3. 循环：while -> `WhileStmtNode`；for to/downto -> `ForStmtNode(isDownto)`。
4. 调用：`procedure_call` 与表达式中函数风格调用统一为 `ProcCallNode`。
5. 表达式：关系/加法/乘法/一元运算分别映射 `BinaryExprNode` 与 `UnaryExprNode`。
6. 复合语句：`begin ... end` -> `CompoundStmtNode`。

### 3.4 变量与数组访问
1. `variable -> IDENTIFIER id_varpart`。
2. `id_varpart` 非空时使用 `buildArrayAccessFromIndices` 将多维下标折叠为嵌套 `ArrayAccessNode`。

## 4. 关键实现设计

### 4.1 二义性处理（if-else）
采用：
1. `%nonassoc LOWER_THAN_ELSE`
2. `%nonassoc ELSE`
3. `IF ... THEN statement %prec LOWER_THAN_ELSE`

效果：`else` 优先匹配最近的未匹配 `if`。

### 4.2 错误恢复策略
采用最小可用恢复策略：
1. `statement_list ';' error`：跳过单条坏语句后继续。
2. 在恢复动作中配合 `yyerrok + yyclearin`，避免同一坏 token 反复触发报错。

该策略可避免“一错全停”，满足课设中“尽可能继续分析后续代码”的目标。

### 4.3 SourcePos 挂载策略（语法侧）
1. 已启用 `%locations`。
2. `YYLLOC_DEFAULT` 中将归约起始位置写入 `g_rule_line/g_rule_column`。
3. `currentPos()` 返回当前归约起始位置，作为节点位置信息。
4. `yyerror` 输出行列与当前词素。

说明：位置信息最终准确性仍依赖词法侧向位置通道提供一致输入。

### 4.4 解析状态重置
`resetParseResult()` 当前会重置：
1. `g_parseRoot`
2. `g_astBuilder`
3. 规则位置缓存（line/column）
4. 语法错误计数 `g_parse_error_count`

保证多次解析之间不会串状态。

### 4.5 RR 冲突治理（2026-04）
问题背景：
1. 在 Bison 构建阶段出现 `reduce/reduce conflict` 告警。
2. 触发位置与复合语句内部空产生式重叠相关。

根因定位：
1. `statement` 允许空。
2. `statement_list` 在旧规则中可由 `statement` 推导，导致间接可空。
3. 复合语句层再允许可选语句列表时，多个非终结符同时可空，产生 RR 冲突。

等价修复策略（不改变原有语义动作）：
1. 引入 `statement_list_opt`，用于承接复合语句中的可选语句列表。
2. 引入 `nonempty_statement`，承接所有非空语句分支。
3. `statement` 保留空语句能力，但 `statement_list` 改为从 `nonempty_statement` 起步，消除间接空重叠。
4. 保留 `statement_list ';' error` 的恢复逻辑，错误恢复策略不变。

兼容性说明：
1. `begin end` 空复合语句仍可通过。
2. 前导分号与空语句场景仍可通过（由 `statement_list_opt` 处理）。
3. AST 建树动作保持原含义，仅规则层做结构化拆分。
4. 对语义分析与代码生成接口无新增字段或调用约束。

### 5.1 与词法模块（C 角色）

2. `ArrayAccessNode.lowerBound` 待语义阶段回填。
3. `ForStmtNode.isDownto` 已在语法阶段准确编码。

## 7. 测试与验收清单（语法模块）

### 7.1 最小语法通过样例
1. 最小程序：program + begin end。
2. 常量声明、变量声明、基础类型。
3. if/if-else、while、for to、for downto。
4. procedure/function 声明与调用。
5. read/write 参数列表。
6. 一元与二元表达式优先级组合。
7. 数组声明与多维访问。

### 7.2 错误恢复样例
1. 缺分号（声明区/语句区）。
2. 语句中非法 token。
3. 括号不匹配与坏语句混合。
4. 多错误同文件，验证可继续分析后续语句。

### 7.3 AST 验收点
1. `ProgramNode` 根非空。
2. `BlockNode` 槽位顺序固定。
3. `ForStmtNode.children.size()==4` 且 `isDownto` 正确。
4. `IfStmtNode` 无 else 时不填第 3 槽。
5. `ListNode.kind` 与语义一致。
6. 关键节点 `SourcePos` 非默认零值（联调时抽样检查）。
