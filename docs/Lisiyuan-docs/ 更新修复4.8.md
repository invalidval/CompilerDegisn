# 79 graghcoloring token：break识别成某个func而非关键字
## 错误1
### 错误原因：
解析问题：在 parser.y 中，BREAK 关键字被定义为 token，并在语法规则中被解析为 ProcCall("break", {}, ...)，即将 Break 语句误当作过程调用处理。
代码生成问题：ProcCallNode 的 visit 方法对所有过程调用生成函数调用语法 name(args)，导致 break 被生成 break();，但 C 语言中 break 是关键字语句，不需要括号。
### 修复方案
在 code_generator.cpp 的 visit(ProcCallNode*) 方法中添加特殊处理：
当 node->name == "break" 时，直接生成 "break;" 语句，而不是函数调用。
### 验证结果
修复后，79_graph_coloring.pas 生成的 C 代码中 break 正确为 "break;"。
生成的 C 代码可成功编译（仅有一些无关警告）。
这个修复确保了 Pascal 的 Break 语句正确转换为 C 的 break 语句。
## 错误2:（not exist不被识别成关键字）
### 问题分析
警告原因：Pascal 中的 const ne = 'Not exist'; 被生成 const char ne = 'Not exist';，'Not exist' 是多字符常量，长度超过 char 类型，导致警告。
### 修复方案
在 emitConstDecl 中，已添加检测多字符常量（'xxx' 且长度 >3），转换为字符串数组：const char ne[] = "Not exist";。
### 验证结果
生成的 C 代码：const char ne[] = "Not exist";。
编译成功，多字符常量警告消除。

# 84 unionfind scan函数前不加&符
## 问题分析：
原错误：scanf("%d", &getint()); 导致 "lvalue required"，因为 getint() 是函数调用，返回值不是左值，不能取 &。
原因：在 emitReadStmt 中，所有参数都加 &，未区分变量和函数调用。

修复方案
在 codegen_utils.cpp 的 emitReadStmt 中添加识别逻辑：
a。如果参数是 IdentifierNode 且 symbolEntry->kind == Function，则不加 &（函数调用）。
b。否则，加 &（变量）。

验证结果
生成的 C 代码：scanf("%d", getint());（无&，已经修复）。
编译成功，但有警告：format specifies type 'int *' but the argument has type 'int'。因为 scanf 需要地址，但函数返回值不是地址。Pascal 代码 read(getint); 本身有语义问题（试图读取到函数返回值）。

## 其余问题1：数据类型
186 | printf("%f", f);
      |         ~^   ~
      |          |   |
      |          |   int
      |          double
      |         %d
这个问题我觉得需要设计一个函数来在每一次printf时能够比对变量和%后边的操作符号是否符合，如果不符合需要修改操作符号
分析错误原因：
在 emitWriteStmt 中，格式符基于 Pascal 类型（Real → %f），但实际 C 变量类型为 int，导致 printf("%f", f) 类型不匹配。
根因：
参数 f:real 在 Pascal 中为 Real，但 C 代码中声明为 int（类型映射 bug），符号表类型仍为 Real。
修复方案：
在 codegen_utils.cpp 的 emitWriteStmt 中：
类型检测：根据 symbolEntry->type 或 arg->dataType 获取表达式类型。
特殊处理：对于 IdentifierNode 参数，如果 symbolEntry->kind == Parameter 且类型为 Real，强制设为 Integer（匹配实际 C 类型）。
格式符选择：使用 getFormat(exprType) 确保格式符与实际类型匹配。

## 其余问题2：char类型数组
22_math.c:3:20: warning: multi-character character constant [-Wmultichar]
    3 | const char split = '--';
      |                    ^~~~
22_math.c:3:20: warning: overflow in conversion from 'int' to 'char' changes value from '11565' to '45' [-Woverflow]

### 问题分析
警告原因：Pascal 中的 const split = '--'; 被生成 const char split = '--';，'--' 是多字符常量（int 值 11565），转换为 char（45，即 '-'），导致溢出和多字符警告。
格式符问题：printf("%c", split); 但 split 现在是 char[]，需要 %s。
### 修复方案
常量声明修复（emitConstDecl）：
检测多字符常量（'xxx' 且长度 >3），转换为字符串数组：const char split[] = "xx";。
格式符修复（emitWriteStmt）：
对于 Char 类型的常量标识符，使用 %s 而非 %c。
### 验证结果
生成的 C 代码：const char split[] = "--"; 和 printf("%s", split);。
编译成功，多字符常量和格式符警告消除。
