## 1. 模块目标

语义分析阶段以 AST 为输入，完成三类工作：
1. 语义约束校验：声明、作用域、调用、表达式、控制语句、数组访问。
2. 语义属性注解：为节点回填 `dataType`、`symbolEntry`、`isLValue` 等信息。
3. 错误汇聚：记录并上报可恢复语义错误，为联调提供高信息密度反馈。

输出为：
- 已注解 AST（可被代码生成直接消费）。
- `ErrorHandler` 中的错误列表。

---

## 2. 架构与阶段位置

编译流水线：
1. 词法分析
2. 语法分析（构建 AST）
3. 语义分析（当前文档范围）
4. 代码生成

语义入口：
- `SemanticAnnotator::annotate(ASTNode* root)`

主程序控制参数：
- `--parse`：仅到语法分析。
- `--semantic`：截止语义分析。
- `--dump-annotated-ast`：输出语义注解后的 AST。

## 3. 关键数据结构

### 3.1 符号类别（SymbolKind）
- Variable
- Constant
- Procedure
- Function
- Parameter

### 3.2 符号项（SymbolEntry）
核心字段：
1. 名字、作用域层级、种类、数据类型。
2. 数组属性：`isArray` + `arrayBounds`。
3. 常量字面量：`hasConstLiteral` + `constLiteralText`。
4. 过程/函数参数：`params`（元素含类型与 var 属性）。

### 3.3 语义节点属性
1. `node->dataType`：节点推导类型。
2. `node->symbolEntry`：绑定符号项。
3. `IdentifierNode::isLValue`：是否可赋值。

---

## 4. 语义遍历策略

整体采用后置 SDT 思路：先建 AST，再做属性求值与约束检查。

执行规则：
1. 深度优先遍历。
2. 表达式先子后父（便于综合属性类型推导）。
3. 语句按语义上下文区分值上下文与非值上下文。

上下文状态：
1. `functionContextStack_`：当前函数返回赋值合法性判断。
2. `valueContextDepth_`：过程调用是否被当成值使用的判断。

---

## 5. 作用域与符号表管理

### 5.1 作用域模型
1. 栈式作用域。
2. `enterScope/exitScope` 管理子程序块。
3. 查找策略为由内向外。

### 5.2 命名策略
1. 名字大小写归一化（不区分大小写）。
2. 同作用域内重定义报错。

### 5.3 程序头参数处理约定
`Program` 的可选头部标识符列表（如 `input/output`）当前作为元信息，不注册为普通变量。若在语句中当变量使用，触发未定义错误。

## 6. 已实现语义规则（按节点）

### 6.1 声明节点

`ConstDecl`：
1. 推导常量值类型。
2. 插入符号表。
3. 重定义检测。

`VarDecl`：
1. 根据类型节点推导声明类型。
2. 若为数组类型，提取维度边界并写入符号项。
3. 变量标识符注解为可赋值左值。

`ParamDecl`：
1. 注册参数符号。
2. 保留 `isVar` 语义。
3. 参数标识符标记为左值。

`ProcDecl/FuncDecl`：
1. 先注册过程/函数条目。
2. 收集形参元信息。
3. 进入子作用域后继续遍历函数体。

### 6.2 语句节点

`AssignStmt`：
1. 左值检查。
2. 类型兼容检查。
3. 支持函数体内“函数名赋值返回值”合法化处理。

`IfStmt`：
1. 条件表达式必须为布尔类型。

`WhileStmt`：
1. 条件表达式必须为布尔类型。

`ForStmt`：
1. 循环变量必须为可赋值整数。
2. 起止边界表达式必须为整数。

`CompoundStmt`：
1. 顺序遍历子语句，不引入新作用域。

### 6.3 调用节点

`ProcCall`：
1. 被调目标必须存在且可调用。
2. 参数个数匹配。
3. 参数类型匹配。
4. var 参数实参必须是左值。
5. procedure 禁止用于值上下文。

### 6.4 表达式节点

`BinaryExpr`：
1. 算术运算：要求数值类型，结果按规则推导。
2. `/`：结果为 real。
3. `div/mod`：仅整数。
4. `and/or`：仅布尔。
5. 关系运算：可比较类型，结果布尔。

`UnaryExpr`：
1. `not` 仅布尔。
2. 一元负号仅数值。

`Literal`：
1. `true/false` -> boolean。
2. 字符字面量 -> char。
3. 含 `.` 或 `e` -> real。
4. 其余 -> integer。

`Identifier`：
1. 查符号并绑定。
2. 未定义报错。
3. 对变量/参数标记左值。

### 6.5 数组节点

`ArrayType`：
1. 从类型节点递归计算元素基类型。

`ArrayAccess`：
1. 下标必须为整数。
2. 支持多维访问深度判断。
3. 支持常量可计算下标越界检查。

## 7. 内建符号预注册

在语义前由 `semantic_register::preregisterBuiltins` 预注册：
1. `read`
2. `write`

效果：
1. 避免基础 I/O 在语义阶段被误判为未定义调用。

## 8. 错误处理机制

错误模型：
1. `line`
2. `column`
3. `message`

策略：
1. 尽量不中断遍历。
2. 单次运行收集尽可能多错误。
3. 主程序统一输出。

典型错误类别：
1. 未定义标识符。
2. 重定义。
3. 调用参数个数/类型/var 属性不匹配。
4. 赋值左值非法。
5. 类型不匹配。
6. 数组越界。
7. 过程用于值上下文。

## 10. 与代码生成接口约定

语义阶段应保证下游可用信息完整：
1. 所有关键表达式节点的 `dataType`。
2. 所有可解析标识符与调用节点的 `symbolEntry`。
3. 过程调用节点的 `isVarParam` 信息。
4. 数组变量的边界元数据（通过符号项持有）。

代码生成阶段默认信任上述语义注解，不重复做核心语义判错。

---

## 11. 当前边界与后续建议

当前边界：
1. 赋值兼容采用严格相等（未做自动类型提升）。
2. Program 头参数采取元信息策略而非文件变量模型。

后续建议：
1. 增加 `integer -> real` 等可配置赋值兼容规则。
2. 扩展更多内建函数（如数学函数）及其参数规则。
3. 增加语义错误码体系，便于 IDE 或自动评测分类。
4. 增加“语义阶段统计输出”（错误数、检查项覆盖率）。
